# Knowledge applicability and conflict projection

INIT-093 supersedes the earlier directional, substring-scoring repair. Retrieval relevance and BM25 ranking retain their existing formulas. Knowledge conflict guards and projection use the same independent two-stage resolver.

`resolveIntrinsicKnowledgeScope` returns `project` with a nonempty project ID set, `workspace-global`, `user`, or `unresolved-legacy`. Explicit metadata project IDs take precedence. Archived null-project records acquire their project set from authenticated consolidation bindings, including coordination bindings. A native workspace/role card outside that archive inventory remains workspace-global. Missing or empty archive provenance is unresolved, never proof of a global domain. Authenticated `replaces` ancestors retain provenance across refreshes. Projection evidence never changes stored metadata or historical events.

Project domains intersect only through a shared project ID. Workspace-global intersects every library project; user intersects user only. Unresolved provenance intersects nothing and is withheld from default retrieval. Query scope selects a view of this fixed applicability; it never creates or resolves a conflict. A global card withheld because of another project's rule stays withheld when that peer is outside the selected view.

The first stage uses Recall's exact bilingual word/CJK-bigram membership, excluding single Han tokens and substring matches. Shared topic alone is Related. The second stage confirms opposite assertions about the same normalized object, or mutually exclusive constraints. It handles explicit negation, operation opposites, exclusive nominal choices and scalar quantities with compatible units and intersecting bounds. Different numbers alone are insufficient: equivalent units, different properties and overlapping bounds remain compatible. Generic negation requires a directive or predicate; detached noun fragments and incidental mentions are insufficient evidence of contradiction. These are explicit rule grammars, not a proof of unrestricted natural-language equivalence.

Confirmed contradiction is symmetric. Writer order, equal timestamps and different INIT families cannot waive it. Existing `coexistsWith` acknowledgements, explicit `--coexist`, supersession, removals, duplicate admission, hash validation and actor attribution retain their semantics. The old public numeric threshold remains available for compatibility, but it no longer defines write-time conflicts. Subject-only completion hints discover candidates and retain their separate family filter and five-card cap.

`knowledge-list` adds `effectiveScope` (library/project/user plus binding), `sourceVersion` (workspace, chain version/head and Crest digest), `projectionVersion`, and `snapshot`. Source identity is independent of query scope. Within one read, `activeCount = eligibleCount + withheldCount + ineligibleCount`. Counts cover active live record versions in the selected domain and metadata filters, before search matching or pagination. Withheld counts include only otherwise retrievable records; overlapping reasons do not count a record twice. Recall uses the explicit retrieval corpus, so an explicit-only card can be eligible there while ineligible in an ordinary default list.

Default diagnostic overhead and empty responses stay below 4096 UTF-8 bytes. `diagnostics` contains exact counts, at most two ID/conflict examples, and `truncated`. Small legacy disclosures are bounded samples; large duplicate metadata is never copied into that summary. When both Recall stores are degraded, oversized repeated legacy disclosures become compact totals with `truncated: true`. Legal card metadata and explicit diagnostic page records retain every byte.

Use `--diagnostics ids|conflicts|audit` with `--diagnostic-limit` (1–256, default 64). Continue using `diagnosticPage.nextOffset` as `--diagnostic-offset` and the first response's `--snapshot`. Continuations require the snapshot. Changed source, scope, time, selection or filters reject with `KNOWLEDGE_SNAPSHOT_CHANGED`; restart the enumeration. `ids` returns every affected ID/reason, `conflicts` every pair, and `audit` every scoped record's metadata digest, intrinsic applicability and eligibility. Ordinary metadata pagination can use the same snapshot pin. `--selection all` retains complete legal metadata for inspection.

The focused regressions cover normal API write admission, delayed device delivery, Chinese/English controls, equivalent negation, exclusive scalar bounds, global/project views, fixed pagination, large legal metadata, dual-store Recall, and old archives with omitted optional fields. Private per-card corpus evidence stays under the ignored `dist/init093/` directory; public fixtures use synthetic identities and technical prose.
