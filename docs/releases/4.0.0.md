# Einzbern 4.0.0

Einzbern and Mana Orchestrate ship in lockstep at 4.0.0.

### Codex independent conversation coordination

- Replace the Codex native collector controller and private bridge with one main
  decision conversation and an independent economy coordinator. Only an
  explicitly selected Codex host uses this workflow; Claude Code, DeepSeek Harness
  and dot retain their existing policies.
- Remove the documented `codexNativeDynamicToolSpecs`,
  `createCodexNativeController`, `createCodexNativeHookBridge` and
  `waitCodexNativeCollector` exports and the `collector-wait` helper. This is a
  breaking change from 3.4.0. Existing isolated controller integrations must move
  to supported host conversation operations and the current coordination contract.
- Add `execution-codex-peer-record` and `execution-codex-peer-evidence` for fixed
  batch recovery. Bind actual conversation identities, worker attempts, work
  revisions, model policy and observation cutoffs; preserve unknown, failed,
  cancelled and completed outcomes without redispatching work.
- Release a worker's occupancy only for a unique, consistent identity association.
  Identity drift, collisions, missing outcomes and conflicting evidence retain
  responsibility. Preserve premature-report findings after later completion;
  final-report association requires terminal evidence strictly before send
  preparation, separately from transport confirmation.
- Guide model setup through stable main, economy and optional flagship categories.
  Main and economy require usable model groups; supplementation preserves user
  selections, custom categories and other hosts. Normal setup retires only proven
  engine-owned collector hooks, preserving user-edited and unrelated entries.
- Keep native scheduling, waiting and report delivery as actual host capabilities.
  Receipt validation and fixture tests do not certify those capabilities, send
  messages, authorize dispatch or establish global exactly-once delivery.

### Device memory admission

- Add an opt-in device memory policy alongside existing heavy-run and agent caps.
  Admit managed work from current process and platform observations, a configured
  reserve and budget, and per-command workload estimates. Missing or uncertain
  required observations refuse dependent work; an unset policy preserves existing
  execution and installation does not enable it.
- Share reservations within the existing local heavy-run resource domain, retain
  process identity and unresolved descendants, and subdivide nested reservations.
  Translate admitted workers to actual Node test concurrency and recheck pressure
  before new work starts without weakening test selection or killing active work.
- Include only the policy in device-preference configuration backups. Exclude
  observations, leases and run receipts; re-evaluate destination memory after
  restore. Sampled process-tree RSS remains an observation, not exact physical
  accounting or an operating-system memory limit.

### Work creation and validation

- Bound validation for owned work-create batches while preserving legacy singleton
  validation, input aliases, inherited-buffer dispatch and staged protocol closure.
  Keep existing admission and rejection behavior outside the optimized batch path.

### CI and release verification

- Separate bounded cloud checks from full local acceptance. Retain the actual
  light roster, raw task streams, source archive and isolated package evidence;
  report omitted full Core, Portal, impact, PF2-H1, P8 and release checks explicitly.
- Verify the actual contributor head and main merge result with full reachable
  privacy history. Recompute retained bytes and reject dirty or mismatched verifier
  sources; loading Python verification helpers does not create source-tree caches.
- Preserve exact offline guard declarations and negative transport probes without
  granting Internet access. Keep private canonical Unix fixture paths within the
  portable socket limit and retain ownership, alias and unexpected-call refusals.
- Decode checkout file URLs before executing verification tools, preserve the
  mandatory test-controller preload in guard fixtures, and retain the acquired
  offline Corepack cache across an isolated HOME. Keep independent CI selection
  expectations aligned with newly required light tests.
